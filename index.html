Sección 1

Definición Estratégica del Caso

Proceso elegido

Gestión end-to-end del desarrollo evolutivo de sitios eCommerce (desde apertura de ticket hasta publicación y medición de impacto).

Problema actual

Los flujos están fragmentados — Desarrollo vive en Jira, Contenido trabaja por fuera, Analytics mide después, Documentación no ocurre. No hay visibilidad unificada del end-to-end ni asistencia inteligente para las decisiones del PM.

Objetivo

Una app (Delivery Hub) que sea la interfaz de una célula híbrida de agentes. No solo muestra datos — ayuda a decidir y actuar.

Justificación del enfoque híbrido

Las decisiones de priorización, aprobación de deploys y validaciones de diseño requieren criterio humano irremplazable. El agente absorbe la complejidad operativa repetitiva; el humano se concentra en decisiones de alto impacto.

Nota sobre Claude vs Codex vs OpenClaw

Claude — elegido para razonamiento y análisis contextual (tareas de PM).

Codex — más orientado a generación de código; no es el caso de uso.

OpenClaw — útil para automatizar interfaces sin API; no necesario porque todos los sistemas tienen API disponible.

Sección 5

Guardrails y Control de Riesgo

Guardrails globales

  • ✓Ningún agente escribe en Jira sin confirmación humana explícita
  • ✓Ningún agente publica documentación sin aprobación del PM
  • ✓Aislamiento por marcaId — un agente no accede a datos de otra marca
  • ✓El agente siempre muestra su razonamiento antes de sugerir
  • ✓Fallback disponible — si la IA falla, la app funciona igual sin ella

Guardrails por agente

PM Analyst: No prioriza — sugiere. Escala si riesgo > umbral.
Implementador: Solo lectura en Jira. Arquitectura escala al Tech Lead.
Documentador: Genera borrador — PM revisa y aprueba antes de publicar.
Healthcheck: No ejecuta cambios. Recomendaciones son sugerencias.

Escenarios de fallo

  • API de Jira no responde → mostrar datos del cache en Sheets
  • Claude API timeout → degradar a modo sin IA, notificar al PM
  • Agente genera sugerencia errónea → PM la descarta, se logea para mejora

Logging y auditoría

  • Cada llamada al agente se registra con timestamp, input y output
  • Las sugerencias aceptadas vs rechazadas se trackean para mejorar prompts
  • El PM puede ver el historial de interacciones con el agente
